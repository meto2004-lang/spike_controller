# Hyena Control — تطبيق التحكم بروبوت SPIKE Prime (Pybricks)

تطبيق مكتمل بـ Python (Tkinter) للتحكم بالروبوت عبر البلوتوث:
إرسال/تشغيل/إيقاف البرامج، استقبال مخرجات الروبوت حيّاً، إدارة الملفات،
وتوليد برنامج سباق من بيانات التدريب المسجّلة.

## التشغيل

طريقة 1: انقر مرتين على `start.bat`
طريقة 2: `python spike_controller.py`

يتطلب **Python 3.11 أو أحدث مع Tcl/Tk**. ثبّت الاعتماديات في بيئة معزولة:

```sh
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux / macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python spike_controller.py
```

على Linux قد تحتاج تثبيت حزمة النظام `python3-tk` من مدير حزم توزيعتك.
`start.bat` يستخدم Python الموجود في `.venv` تلقائياً إن وُجد، ويفحص المتطلبات ثم يشغّل التطبيق بالمفسّر نفسه. تبقى نافذة الكونسول ظاهرة لعرض الأخطاء، ويتوقف المشغّل عند الفشل بدلاً من إخفاء المشكلة. تحتاج ميزات USB كذلك تعريفات وصلاحيات مناسبة للمنصة؛ وجود الاعتماديات لا يضمن أن الفرموير يدعم الرفع بالسلك.

## المميزات

| المجموعة | الميزات |
|---|---|
| الاتصال | مسح تلقائي مع 6 محاولات، مدة مسح 20 ثانية (موثوق مع كرت CSR) — + اتصال بالسلك USB (فحص + بث استقبال COM) |
| البرامج | إرسال وتشغيل ▶، إرسال مع الانتظار ⏳، تحميل فقط ⤓، تشغيل المخزن ↺، إيقاف ■ |
| الاستقبال | عرض حيّ لمخرجات الروبوت، طوابع زمنية، حفظ تلقائي في logs، تصدير يدوي |
| المحرر | تبويبات مستقلة، تلوين صيغة بايثون، أرقام أسطر، قوالب جاهزة (إعدادات الروبوت، حلقات، حساسات) |
| الملفات | جديد/فتح/حفظ/حفظ باسم، آخر 6 ملفات، فتح مجلد السجلات |
| السباق | زر «توليد ملف سباق» يستخرج robot.straight/turn وتعليقات الحساسات من الكونسول |
| اللغة | عرض صحيح للنص العربي في الكونسول والمساعدة (RTL عبر `arabic-reshaper` + `python-bidi`) — النسخة الخام تُستخدم للتحليل فلا تتأثر ملفات السباق |
| الحالة | مؤشر الاتصال، حالة البرنامج (يعمل/متوقف)، تحذير البطارية المنخفضة |
| اختصارات | F5 إرسال وتشغيل، Ctrl+F5 مع الانتظار، Esc إيقاف، F1 مساعدة، Ctrl+G توليد سباق، Ctrl+L جلسة جديدة ومسح البيانات |

## الاتصال بالسلك (USB)

| الزر | الوظيفة |
|---|---|
| **اتصال بالسلك ▶** | يفحص الكابل وواجهات USB — إن وُجدت واجهة Pybricks (0xFF) يتصل ويتحكم بالكامل عبر السلك |
| **بث السلك ▶** | يفتح منفذ الروبوت (COM) ويعرض أي بيانات يصله في الكونسول مع بادئة `[سلك]` |

> ⚠️ **ملاحظة مهمة:** فيرموير Pybricks الرسمي 4.x لـ SPIKE Prime يعرض على السلك
> منفذ COM فقط (CDC) — **بدون واجهة لرفع البرامج**. هذا مؤكد رسمياً من فريق
> Pybricks: الدعم التجريبي للسلك يتطلب بنناً مخصصاً للفيرموير من
> [labs.pybricks.com](https://labs.pybricks.com/) (تجريبي — غير موصى به قبل المسابقة).
> لذلك **الرفع والتشغيل يتمان عبر البلوتوث**، والسلك متاح للاستقبال والشحن.
> عند تثبيت فيرموير يدعم USB مستقبلاً سيعمل زر «اتصال بالسلك» تلقائياً بكامل وظائفه.

## دورة التدريب الموصى بها

1. اكتب/افتح برنامج التدريب في المحرر ← «إرسال وتشغيل»
2. خذ الروبوت للسجادة ودرّب بالزرار (RIGHT حركة، LEFT حساسان، LEFT+RIGHT حذف)
3. ارجع بالروبوت ← البرنامج ما زال يعمل ← اضغط «اتصال» في التطبيق
   (الاتصال فقط لا يمسح التسجيل — تجنب «إرسال وتشغيل» أثناء التدريب!)
4. اضغط «جلسة جديدة / مسح» **قبل** الضغط على CENTER لطباعة تسجيل كامل جديد؛ هذا يمسح بيانات الجلسة السابقة من الذاكرة والعرض بعد التأكيد، ولا يحذف السجلات المحفوظة على القرص.
5. اضغط CENTER في الروبوت ← تظهر جميع التسجيلات في الكونسول
6. اضغط «توليد ملف سباق» ← راجع ← «حفظ كملف» ← أرسله وشغّله

### مكان الإعدادات والسجلات

يُنشأ `spike_controller_config.json` ومجلد `logs/` داخل مجلد بيانات المستخدم:

- Windows: `%LOCALAPPDATA%\HyenaControl`
- Linux/macOS: `$XDG_STATE_HOME/HyenaControl` أو `~/.local/state/HyenaControl`
- يمكن تخصيص المسار بمتغير البيئة `HYENA_CONTROL_DATA_DIR`.

يقرأ التطبيق الإعدادات القديمة الموجودة بجوار البرنامج إذا لم توجد إعدادات جديدة؛ السجلات القديمة لا تُنقل أو تُحذف. استخدم «فتح مجلد السجلات» للوصول إلى المجلد الحالي. أسماء سجلات الروبوت فريدة ولا تستبدل ملفات سابقة.

## تبويبات الملفات

- «جديد» أو `Ctrl+N` أو زر `+` يفتح تبويباً جديداً؛ فتح ملف أو اختياره من الملفات الأخيرة لا يستبدل أي تبويب.
- فتح الملف نفسه مرة أخرى يختار تبويبه الموجود ويحافظ على تعديلاته غير المحفوظة. تُميّز الملفات ذات الاسم نفسه بمسارات المجلدات على التبويبات.
- لكل تبويب نص مستقل وتراجع/إعادة ومؤشر وتمرير وأرقام أسطر وتلوين، وعلامة `*` عند اختلاف النص عن آخر نسخة محفوظة.
- `Ctrl+S` يحفظ التبويب النشط، و`Ctrl+Shift+S` يحفظه باسم جديد. يُمنع الحفظ فوق ملف يمتلكه تبويب آخر مفتوح.
- `Ctrl+Tab` و`Ctrl+Shift+Tab` للتنقل. أغلق بالتقاطع `×` على التبويب أو زر الإغلاق أو `Ctrl+W`؛ تُعرض خيارات حفظ/تجاهل/إلغاء عند وجود تعديلات. إلغاء الحفظ أو فشله يبقي التبويب مفتوحاً، وإغلاق آخر تبويب ينشئ تبويباً نظيفاً.
- عند إغلاق التطبيق تُراجع **كل** التبويبات المعدلة قبل إزالة أي تبويب أو بدء قطع الاتصال. اختيار الإلغاء يبقي التطبيق والاتصال مفتوحين؛ الملفات التي اخترت حفظها قبل الإلغاء تبقى محفوظة.
- الإرسال والتحميل يحفظان التبويب المقصود أولاً ويثبتان مسار الملف للعملية؛ يظهر اسم ملف العملية ومجلده في سطر مستقل أسفل الأزرار حتى عند الانتقال إلى تبويب آخر. تبديل التبويب لا يرسل برنامجاً ولا يوقف الروبوت. الإيقاف وتشغيل البرنامج المخزّن يخصان الروبوت لا التبويب.
- الاتصال والكونسول وبيانات التدريب مشتركة بين التبويبات. هذه المرحلة لا تشمل السحب لإعادة الترتيب أو حفظ الكل أو استعادة التبويبات بعد إعادة التشغيل أو التعطل؛ احفظ الملفات قبل الخروج.

### العربية داخل محرر الكود

محرر `Tk Text` لا يوفر دعماً كاملاً لاتجاه العربية المختلطة بالكود. لذلك تضاف **معاينة عربية للسطر الحالي** أسفل المحرر، بدلاً من إعادة تشكيل مصدر البرنامج نفسه:

- تتحدث المعاينة عند الكتابة أو تحريك المؤشر أو تبديل التبويب، وتعرض الحروف العربية بشكل متصل وترتيب بصري مناسب عند تثبيت اعتماديات التشغيل.
- زر «معاينة العربية» أعلى المحرر يخفي اللوحة أو يظهرها لتوفير مساحة للكتابة.
- اللوحة للقراءة فقط. زر «نسخ السطر الأصلي» أو النسخ من المعاينة ينسخ **السطر المنطقي الأصلي كاملاً**، لا النص المعاد تشكيله، حتى عند تحديد جزء من المعاينة. لا تصدّر اللوحة تحديداً بصرياً إلى حافظة التحديد في Linux.
- تُختصر معاينة الأسطر التي تتجاوز 2000 محرف؛ يبقى النسخ شاملاً للسطر الأصلي كاملاً.
- لا تتغير التعليقات أو السلاسل البرمجية أو سجل التراجع أو حالة الحفظ بسبب المعاينة. الحفظ والإرسال يستخدمان المصدر الأصلي دائماً.
- **هذا حل للقراءة، وليس إصلاحاً للتحرير العربي داخل السطر نفسه.** يظل هذا القيد موجوداً في محرر Tk. عند غياب مكتبات تشكيل العربية تظهر رسالة تطلب تثبيت `requirements.txt`.

## ضمانات الحفظ والتدريب

- يمكن إدخال اسم الروبوت (كما يظهر في الإعلان) أو عنوان BLE في شريط الاتصال. إن تركته فارغاً تُطلب موافقة صريحة قبل الاتصال بأول روبوت متاح؛ استخدم اسماً مميزاً أو عنواناً عند وجود أجهزة متعددة.

- يظهر اسم الملف المفتوح بوضوح أعلى المحرر وفي عنوان النافذة، ويظهر مساره الكامل في حقل للقراءة فقط يمكن تحديده ونسخه، بدلاً من الاعتماد على شريط الحالة المزدحم.
- تظهر `*` بجوار اسم الملف عند تعديله، وتُحفظ التعديلات قبل الإرسال. فشل الحفظ أو إلغاؤه يمنع الرفع.
- «فتح في تبويب جديد» من نافذة السباق ينشئ وثيقة جديدة غير محفوظة باسم مقترح للسباق، ويترك ملف التدريب وتعديلاته في تبويبه دون استبدال.
- لا تجمع تسجيلات متعددة في جلسة واحدة. إعادة طباعة التسجيل الكامل داخل الجلسة تضيفه مرة أخرى؛ التكرارات قد تكون مقصودة ولذلك لا تُحذف آلياً.
- يفصل المولّد بيانات التدريب الخام عن رسائل التطبيق وعن بادئة `[سلك]` المرئية.
- عند فقد بيانات بسبب الانقطاع غير المتوقع أو ازدحام الاستقبال أو تجاوز الحدود يُمنع التوليد حتى بدء جلسة جديدة واستقبال التدريب كاملاً. قطع الاتصال عمداً بعد اكتمال الاستقبال لا يُبطل بيانات التدريب المكتملة.
- انتظر اكتمال الاستقبال ومعالجة الرسائل قبل التوليد. وصول مخرجات جديدة يُبطل المعاينة القديمة حتى داخل الجلسة نفسها، ويُلزم تحديثها. يُعاد التحقق بعد نافذة اختيار ملف الحفظ وقبل فتح تبويب السباق، لمنع استخدام معاينة أصبحت قديمة.
- المولّد يقبل أوامر حرفية فقط: `robot.straight(distance)` و`robot.turn(angle)` و`robot.stop()` و`robot.drive(speed, turn_rate)`، دون معاملات مسمّاة أو تعبيرات تنفيذية أو تعليمات إضافية.
- حدود الإدخال: مسافة ±10000 مم، دوران ±3600 درجة، ومعاملَا `drive` ضمن ±1000 بوحداتهما. هذه حدود تحقق **وليست ضماناً لسلامة الحركة**؛ راجع السرعات والمقاسات والمسار يدوياً، خصوصاً أن `drive` مستمر وغير حاجب.
- Esc يلغي العملية الجارية وينتظر تنظيفها ثم يرسل إيقاف البرنامج إن وجد اتصال. لا تغلق التطبيق كبديل عن زر الإيقاف؛ قطع الاتصال لا يعني إيقاف برنامج الروبوت.

اختبارات المنطق تعمل دون روبوت ودون تثبيت اعتماديات التشغيل، مع بدائل للواجهة والعتاد. لتجربة بناء واجهة Tk على جهاز يدعم العرض:

## تشخيص خطأ GATT أثناء الإرسال (خصوصاً مع فرموير 4.1.0)

`BleakGATTProtocolError: (14, 'GATT Protocol Error: Unlikely Error')` لا يحدد سبباً واحداً، ولا يعني بمفرده أن ملف Python أو الفرموير يحتاج إلى استبدال. في مصدر فرموير 4.1.0 توجد مهلة نقل تبلغ ثانية واحدة تُجدّد مع وصول البيانات، وأخطاء حالة النقل قد تتحول إلى `0x0E`؛ لكن تعيين هذا السبب على جهاز معين يحتاج سجلاً واختباراً فعلياً:

- [مصدر تخزين البرامج في فرموير 4.1.0](https://github.com/pybricks/pybricks-micropython/blob/v4.1.0/lib/pbio/sys/storage.c)
- [تحويل أخطاء البروتوكول في فرموير 4.1.0](https://github.com/pybricks/pybricks-micropython/blob/v4.1.0/lib/pbio/src/protocol/pybricks.c)

إجراءات التطبيق الجديدة:

- يحد حجم كتابة حزم الرفع عبر BLE إلى **20 بايت** (تشمل ترويسة أمر Pybricks) لتفادي الحاجة إلى كتابة BLE طويلة على بعض المحولات. هذا يقلل السرعة، وهو إجراء توافق احترازي وليس علاجاً مضموناً لكل خطأ `0x0E`. لا يُطبق على USB ولا يعدّل Bleak عالمياً.
- ينتظر انتهاء البرنامج وحالة إدخال/إخراج الملفات، بمهلة محدودة، بدلاً من افتراض جاهزية الروبوت بعد نصف ثانية.
- يفصل تنزيل الملف عن أمر تشغيله على الفرموير الحديث؛ لا يبدأ البرنامج إذا فشل الرفع، ولا يعيد أمر التشغيل تلقائياً إذا فشل إقراره.
- يمنع «تشغيل المخزن» بعد فشل رفع أو إلغائه حتى يكتمل رفع جديد بنجاح خلال جلسة التطبيق الحالية.
- يعرض رسائل ASCII واضحة، منها `phase=stop-ready` و`phase=compile-upload` و`phase=upload-ready` و`phase=start`؛ في وضع انتظار نهاية البرنامج تظهر `phase=start-wait`.
- يسجل إصدار الفرموير و`pybricksdev` و`bleak`، ويحفظ الاستثناء الكامل في `logs/transfer_errors.log` داخل **مجلد بيانات المستخدم** الموضح أعلاه.

إذا استمر الخطأ، أغلق اتصال Pybricks Code وأي تطبيق آخر متصل، ثم أعد الاتصال. بعد حفظ تسجيل التدريب المهم، جرّب ملفاً بلا حركة مثل `print("SPIKE OK")` وأرسل أسطر `[TX]` وملف `transfer_errors.log`. لا تعد تثبيت الفرموير بناءً على هذه الرسالة فقط. حدود الحزم وانتظار الجاهزية مختبرة برمجياً، لكن نجاح النقل الفعلي يحتاج تجربة على الـHub ومحول البلوتوث المستهدفين.
